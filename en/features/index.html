    Language features

    The full list with evidence lives in docs/TAALFEATURES_28sep.md. These are the highlights.

    Speed

    • Roughly 4% faster than hand-written C: on average 95.9% of the C time, measured across 11 scenarios. Evidence is in the repository.
    • Versus Python: arithmetic 3,049×, loop-summing 35.4×, matrices 21.2×.

    Two production backends, bit-exact

    • The C backend passes 240/240, the LLVM backend 309/309, and the pitfall suite is 18/18 bit-exact identical between the two.
    • Two independent code paths mean one bug in one backend doesn't take the whole product down.

    Compiles itself, since May 2026

    • Fixed-point test: the compiler compiles itself, and that new compiler produces exactly itself again. That is the criterion GCC and Zig have to meet.
    • All 228 modules compile through the own 840 KB binary.

    Translation by intent

    • Our translators look at what code means, not at its letters. A COBOL COPY loop becomes an alias, so the loop disappears entirely; a folding sum becomes a built-in kernel.
    • The same approach for COBOL, VB6, Python and RPG.

    Runtime

    • VM Supervisor: hot-swapping parts, rollback and crash isolation following the BEAM model.
    • HAL Adaptive Dispatch: GPUs come and go while your code runs, with bit-exact recovery.
    • AI alongside, not built in: the language itself contains no AI and forces nothing on you. When you want a model, NC talks to it on our own kernels — no external service, no API key. Proven down to a 2017 GPU: 41.7 tok/s, bit-exact.
    • Self-improvement built in: A/B tests with gates and rollback (NIP).
    • Also: an ownership system, 470 built-in functions, automatic AVX2 vectorization, OpenMP and a REPL.

    Working with what you already have

    • Use Python and speed it up: port the slow parts to NC — measured gains up to 35.4× (loops) and 3,049× (arithmetic) — and keep the rest in Python. The Python-to-NC converter (2,517 lines, 32 AST handlers) does the heavy lifting automatically.
    • C libraries: NC calls native C libraries directly; all 240 stdlib modules compile against the same runtime.
    • noodle run analyses a Python script and accelerates the functions where the time goes. Actively being developed.
    • COBOL, VB6 and RPG teams port over using the same intent-based approach.

    Honest about speed

    We prefer to tell you where you win, and where you don't.

    Situation Result Why
    Arithmetic loops (summing, number crunching) up to 3,049× the interpreter disappears: per-iteration bytecode becomes machine code
    Matrix math 21.2× AVX2 vectorization computes 8 floats per clock cycle
    Text processing large, see the Examples exactly where Python's interpreter tax is biggest
    Database queries up to 1.8× faster than SQLite (measured per query type) an engine without copy layers between memory and disk
    Scripts waiting on network or disk equal the wait is the bottleneck, not the language
    Code already computing in C (NumPy etc.) roughly equal the math is already native; only the glue around it speeds up
    One-off half-second scripts not worth it compile time outweighs the gain

    Rule of thumb: NoodleCore removes the interpreter tax — the translation per line and per iteration. What is already machine code, or waits on disk or network, no language can speed up.

    NoodleDB in the standard library

    • One engine, five faces: relational, graph, vector, full-text, time series.
    • SQL is the door, not the house: BFS and Dijkstra algorithms (76/76), HNSW vector search and full-text search are built in.
