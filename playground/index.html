    Demo 1: priemgetallen (zeef van 1 miljoen)

    Een klassieke reken-loop: hetzelfde algoritme, twee talen. Zo zie je wat compilatie naar native C oplevert zonder dat je zelf iets verandert.

    Python

    def sieve(limit):
    flags = bytearray([1]) * (limit + 1)
    flags[0] = flags[1] = 0
    for i in range(2, int(limit**0.5) + 1):
        if flags[i]:
            for j in range(i*i, limit + 1, i):
                flags[j] = 0
    return sum(flags)

    NoodleCore

    fn sieve(limit: int) -> int {
    var flags = arr_new(limit + 1, 1)
    flags[0] = 0
    flags[1] = 0
    var i = 2
    while i * i <= limit {
        if flags[i] == 1 {
            var j = i * i
            while j <= limit {
                flags[j] = 0
                j = j + i
            }
        }
        i = i + 1
    }
    return arr_sum(flags)
}

    Demo 2: tekstverwerking (CSV-parser, 1 miljoen regels)

    Tekst is waar Python het zwaarst wordt en NC het duidelijkst wint: dezelfde regels lezen, splitsen en tellen, zonder tolkosten.

    Python

    import csv

def count_bigger(rows, field, threshold):
    n = 0
    for row in csv.reader(rows):
        if row and float(row[field]) > threshold:
            n += 1
    return n

    NoodleCore

    fn count_bigger(rows: str[], field: int, threshold: f64) -> int {
    var n = 0
    for row in rows {
        var parts = str_split(row, ",")
        if parts.len > 0 {
            if str_to_f64(parts[field]) > threshold {
                n = n + 1
            }
        }
    }
    return n
}

    Demo 3: database (NoodleDB tegen SQLite)

    De derde pijler: de database zit in de taal. Dezelfde soorten vragen, A/B gemeten op identieke machines: op alle 16 query-types sneller dan SQLite, tot 377.590 transacties per seconde.

    Python + sqlite3

    import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE t(x INTEGER, y REAL)")
for i in range(1_000_000):
    con.execute("INSERT INTO t VALUES (?, ?)", (i, i * 0.5))
con.commit()
n = con.execute(
    "SELECT COUNT(*) FROM t WHERE y > 250000"
).fetchone()[0]

    Gemeten (iMac Pro, A/B-getest)

    Operatie SQLite NoodleDB Winst
    INSERT (1k rijen) trager 4,7 ms sneller
    SELECT WHERE (1k) trager 3,6 ms sneller
    TRANSACTIE (1k) 2,6 ms gem. 377.590 per sec sneller
    16 query-types — — 16/16 NC

    NoodleCore + NoodleDB

    use noodledb_sql

fn main() -> int {
    db = ndb_open(":memory:")
    ndb_exec(db, "CREATE TABLE t(x INTEGER, y REAL)")
    var i = 0
    while i < 1000000 {
        ndb_exec(db, "INSERT INTO t VALUES (" +
                 str_from_int(i) + ", " +
                 str_from_f64(i * 0.5) + ")")
        i = i + 1
    }
    var n = ndb_query_int(db,
        "SELECT COUNT(*) FROM t WHERE y > 250000")
    return n
}

    Eerlijke kanttekening

    De winst hangt af van het soort werk: hoe meer zuiver rekenwerk en hoe zwaarder de tolkosten van Python, hoe groter de winst. Scripts die vooral op de schijf of het netwerk wachten, winnen weinig. Daarom porten wij de trage delen, geen hele programma's, en daarom publiceren wij per claim de methodiek.
